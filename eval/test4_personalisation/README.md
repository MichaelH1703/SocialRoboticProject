# Test 4 – Personalisation

Ten sessions run through `reachy_text_chat.py` (unchanged, saving off) as
April: 5 with her context (W1–W5) and 5 as a blank April with no context
(B1–B5), run alternately.

April is played by a simulated child (`../simulated_child.py`, llama3.2:3b, a
different model from Reachy's qwen2.5:3b). It answers what Reachy actually
asks, in a short style, from a fixed fact sheet about one day: bowling for
Mia's birthday. It never sees April's profile, notes or lesson plan, or which
condition it is in. Every session has the same shape:
- a fixed opening, "Yeah. Went bowling.", so the same event is picked every time;
- 11 generated answers, one of which is a forced "I don't know" given in answer
  to a question;
- "Bye." and "No." to end.

Sessions with the same number (W1/B1 …) share the child's random seed. Each of
April's lines is checked against the robot's own safety and goodbye rules, and
against her fact sheet, and is regenerated if it fails.

A first attempt with a fixed child script was discarded because the child's
lines ignored Reachy's questions. It was not rated.
The two pilot sessions that tuned the simulated child are in `pilot/`.

## Your part, in this order

**Do not open `_unblinding/` until steps 1 and 2 are done.** It names the
condition of every reply and session.

1. **Rate the replies blind.** `blind_replies.tsv` has 40 replies (20 from each
   condition, 4 per session, picked and shuffled with a fixed seed). Paste the
   rows into the sheet's bottom table and score each on the Test 3 scale.
2. **Code the sessions blind.** Read `blind_sessions/S01.txt`–`S10.txt` and fill
   in `blind_session_coding.tsv` using the rules in `criteria.md`. Those rules
   were fixed before the runs.
3. **Un-blind.** `_unblinding/key_replies.tsv` gives each reply's condition, and
   `_unblinding/key_sessions.tsv` maps S01–S10 back to W1–B5.
   `_unblinding/top_table.tsv` is the sheet's top table, with mean words per
   reply filled in and the Y/N columns left for your coding.

## Results

Un-blinded with `finalise.py` once the ratings and coding were final. Results
are in `results/`: `summary.md` has all the numbers and tests, and the three
`.tsv` files are paste-ready for the sheet.

## What is in the database

April under `eval-test@reachy.local` now has a profile, one session note, one
recap session with a lesson plan, and 3 event titles. The lesson plan was
generated by `lesson_planner.py` from the recap transcript, as the dashboard
does it. `eval-test-blank@reachy.local` was created with no password, so it
cannot log in. It has an April (14) with the same 3 event titles and nothing
else. Every row added is listed in `setup_rows.json`. `cleanup.sql` removes
them all and puts April's profile back to empty.

After Test 4 was run, Test 3 added a 4th and 5th event title to both Aprils
(`../test3_reply_quality/add_event_titles.py`). Test 4 itself ran with 3. Run
Test 3's `cleanup.sql` before this one.

## Files

| File | What it is |
|---|---|
| `materials.json` | Profile, note, recap transcript, event titles, the simulated child's fact sheet and settings, run order, seed |
| `lesson_plan.txt` | The generated lesson plan, used as-is |
| `criteria.md` | Coding rules, fixed before the runs |
| `setup_db.py` | Seeds the database (refuses to run twice) |
| `run_sim_sessions.py` | `check` compares the two prompts; `pilot` and `run` run sessions |
| `analyse.py` | Builds the blind sheets, keys and stats from the raw logs |
| `_unblinding/prompt_with.txt`, `prompt_without.txt` | The full system prompt each condition got. They differ only in BACKGROUND |
| `_unblinding/raw/` | Full console output of every session, including the simulated child's notes |
| `_unblinding/session_stats.tsv` | Counts per session, plus keyword checks to cross-check your coding |
